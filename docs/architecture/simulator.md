# Simulator (replay a month)

Status: draft
Owner: eldon

BPL-018. Replays one month of the owner's own records on the compiled tenant and compares what the tenant reports with totals computed from the source. Optional for G1 ([ADR-0026](../decisions/ADR-0026-phased-delivery-and-market-pack-track.md)); planned for G2 ([GATES](../GATES.md)). Code: [services/blueprint/simulator/](../../services/blueprint/simulator/__init__.py). The report is rendered by BPL-019 and measured by QA-011.

## Pipeline
1. **Input model** (`model.py`). The `accepted` rows of a pre-validation report (DSC-019, fed by DSC-011 and DSC-014) are grouped by (type, number) into source records: `stock_in`, `purchase_invoice`, `payment_out`, `stock_out`, `sales_invoice`, `payment_in`, `payroll_run`. Each record keeps its provenance (connector, sheet, row, row SHA-256) and the intake's finding codes. Amounts are exact decimals: a float, an unparseable amount or date, or an unknown currency drops the record (SIM-114).
2. **Source checks** (`anomalies.py`). Flags, never corrections: date outside the month (excluded), missing or unknown tax code, unmapped account, negative stock, duplicate document number (excluded), possible duplicate, payment not allocated to an invoice of the month, document-total rounding.
3. **Replay planner** (`plan.py`). Records in order of posting date, then a fixed same-day kind order (receipts before issues, bills before payments). Each record becomes a `create` call and, when the mapping says so, a posting call (`submit` or a named transition). Calls are Tool API calls from the tenant's generated tool set ([contract 3](../../contracts/tool-api.md)), never raw writes. Risk comes from the tool set: R0 to R2 run, R3 and R4 are recorded as "would need approval" and never sent; an unknown risk is R4. The caller is the replay user with the tenant's own roles; a tool that none of those roles may call is refused at planning (the gateway re-checks). Arguments are checked against the tool's input schema before anything is sent. Idempotency keys are UUIDv5 of (tenant, period, run epoch, source record, stage): a rerun sends the same keys and converges; a changed record under the same key gets `idempotency_conflict` and stops the run. A deliberate fresh run uses a new `run_epoch`.
4. **Runner and port** (`runner.py`). `EnginePort` has two operations: `execute(ToolCall)` returning a Tool API response, and `report_totals(tenant, caller, period)` returning `{metric: {currency: decimal string}}`. Fail closed: an exception, an `error` response or a malformed response stops the run, later steps are `not_run`, totals are not read and nothing is compared (`aborted`). A call parked by a Blueprint approval rule (`pending_approval`) is recorded, not executed.
5. **Comparison** (`compare.py`). Expected totals from source: sales and purchases (net), VAT output and input, receivable and payable aging buckets at month end, stock value (moving average per item and warehouse), payroll gross, deductions and net. Per-document rounding half up at the currency exponent, integers in minor units, Decimal only. Tolerance per metric (or family, or `default`): `abs_minor + per_document_minor x documents`, zero by default. A metric that needs a held R3 or R4 step is `blocked_by_approval`, not compared.
6. **Report** (`report.py`, [report.schema.json](../../services/blueprint/simulator/report.schema.json)). Steps with action and outcome, comparison rows, SIM-xxx anomalies with i18n message keys, excluded records, summary counts and empty owner and accountant sign-off fields. No timestamps and no free text: same inputs give the same report and `simulationId`.

## Anomaly codes
SIM-101 unmapped account, SIM-102 rounding difference, SIM-103 missing tax code, SIM-104 negative stock, SIM-105 duplicate document, SIM-106 possible duplicate, SIM-107 date outside month, SIM-108 no tool for the record, SIM-109 needs approval, SIM-110 caller lacks role, SIM-111 invalid arguments, SIM-112 intake quality flag, SIM-113 unallocated payment, SIM-114 invalid source value, SIM-115 inconsistent document, SIM-116 unknown record kind, SIM-117 step blocked by an earlier step, SIM-118 parked by an approval rule, SIM-120 port error (run aborted), SIM-121 total mismatch, SIM-122 metric not compared, SIM-123 invalid reported amount. Severities and keys live in `codes.py`. Params can carry source text (party, account, type); BPL-019 renders them as escaped data.

## Real engine versus simulated port
CI has no real tenant. `SimulatedPort` stands in: tool lookup, role pre-check, R3 and R4 parked, idempotency, draft and posted documents, line-level tax from the tenant's tax rates, moving-average valuation and aging on posted documents. It models behaviour only and is no evidence about the engine (UNVERIFIED). A gateway-backed port (Tool API calls on the replay user's session, totals through `report.run` or `metric.query`) replaces it without changing the planner, runner or comparison.
