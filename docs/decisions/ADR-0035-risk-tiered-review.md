# ADR-0035: risk-tiered review and fewer rounds

Status: Proposed
Owner: eldon
Approved by: pending (both founders must agree; it changes approval gates, so the partner's recorded review is required, ADR-0032)

## Context
Review effort is now the main cost. Every PR gets the same review from two founders and their agents, comments pile up on each PR, stacked PRs and the generated `docs/STATUS.md` cause repeated conflict merges, and specs for later gates are being reviewed while the current gate (G0) is open. A docs fix costs as much as tax code.

## Decision
1. **Three review tiers by what the PR touches.**
   - **Tier 1, docs only** (`docs/` except `docs/decisions/`, `docs/security/`, `docs/compliance/` and `docs/legal/`; logs; plan rows; status): merges after CI is green. The other founder skims afterwards in a batch and raises a follow-up if something is wrong.
   - **Tier 2, ordinary code, contracts, ADRs, scripts, CI:** one review from the other founder, with a different model than the author's.
   - **Tier 3, rigid zone and security** (tax, e-invoicing, ledger-adjacent, auth, tenancy, policy enforcement, secrets handling): full review as today, including ADR-0031 line-by-line human review and the security review.
2. **Block only on real defects.** A review blocks only for a bug, a security issue, a broken rule or a missing required check. Everything else is a follow-up plan row or open question, not a change request. Agent reviewers follow the same rule and list blocking items first.
3. **At most two review rounds** per PR. After the second, the founders settle it in one message and record the outcome in the PR.
4. **Fewer, larger PRs.** One PR per feature or topic, not one per plan row; avoid stacks deeper than two. One plan row per PR rule (AGENTS.md) stays, a PR may close several rows of one topic.
5. **Logs for code PRs only.** A docs-only (Tier 1) PR needs no session log.
6. **Stay at the current gate.** Do not draft specs or ADRs for a later gate while the current gate has open rows, unless a founder asks.
7. **Generated STATUS.** `docs/STATUS.md` is regenerated by CI and no longer committed by authors (follow-up).

## Alternatives rejected
- Keep one review level for everything: the cost we are trying to cut.
- No review for code: unacceptable for money, tax and tenancy (ADR-0031, ADR-0032).

## Consequences
- **Mechanism UNVERIFIED:** ADR-0032 says `main` requires one approving code-owner review. GitHub cannot waive that for docs-only PRs without a ruleset bypass or a path-based rule. The founders must pick one: a bypass for docs-only PRs, a quick approval with batch reading, or a path-based ruleset. Until then Tier 1 PRs still need the click, but not a read.
- Follow-ups: `scripts/` and CI change to generate STATUS; update `AGENTS.md`, `docs/RULES.md` and PR template wording after acceptance; GOV-042 (efficient review workflow) stays and sits under these tiers.
- Plan: GOV-043.

## Supersedes
None. Narrows how ADR-0032 is applied (approval is still a recorded review); does not change ADR-0031.
