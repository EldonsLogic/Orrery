# ADR-0064: Scheduled agents: owner authority, draft-only runs and two-level budgets

Status: Proposed
Owner: eldon
Approved by: pending (Tier 3: agent authority and budgets; needs the other founder's line-by-line review and a different-model security review)

## Context
OPR-013 adds agents that run on a cadence with no human in the turn. [ADR-0048](ADR-0048-agent-authority-propose-not-act.md) (Proposed) says OPR-013 must conform to it but does not say whose authority a scheduled run carries, how its budget is held across runs, or what happens when the owner loses access. [agent-least-privilege](../security/agent-least-privilege.md) sets the on-behalf-of user to the owner (OQ-1 open) and ALP-019, ALP-025, ALP-026, ALP-031 and ALP-033. The model-call contract ([model-call.md](../../contracts/model-call.md), [ADR-0054](ADR-0054-model-call-contract.md), Proposed) reserves and meters per call but has no standalone period reservation. First slice: `services/operate/runtime/schedule.py`.

## Decision
1. **Owner authority, never more.** A schedule's tenant and owner come from the verified principal (role ids must be a tuple of strings); a body tenant or owner that differs is refused (`tenant_mismatch`, `owner_mismatch`). Its agent role must be one of the owner's own roles (`role_escalation`); no caller-supplied role field exists. Its tools must be on that one role's agent menu (`resolve_allowlist`, `tool_not_allowed`). Reading spend or holds needs the owner's principal.
2. **Draft-only.** A scheduled tool is refused (`draft_only`) when it is R2, refused by `authority.tool_refusal`, an `export` (egress, Tool API section 11), a transition tool or a tool with `transitions[]`, or a non-read tool that is not declared `kind: write` and `entity_class: plain` (a missing kind or class is never plain), is a posting entity, or has a rigid-zone name token (invoice, einvoice, zatca, fatoora, tax, vat, payroll, salary, payslip, wps, ledger, journal, gl, posting). Reads are `get` and `list` with `kind: read`. A run only records proposals for the human review queue; nothing executes. Drafts are re-checked at the end of the run, their args copied, and each draft and run record is marked tainted.
3. **The run sees a narrow context.** The agent gets only `caller`, `complete` and `draft`. The port sits behind a private wrapper that forces `thread_tainted` (ALP-019), meters the run itself and enforces a wall-clock limit (`run_timeout`). This is defence in depth inside one process, not a sandbox: agent code is platform code, never model output.
4. **Re-checked at run time.** The owner's current roles are read before each run; losing the agent role suspends the schedule (`owner_permission_lost`, ALP-026), a failing role store is `roles_unavailable`. Tools are re-resolved before the first model call and again at the end. Three consecutive failed runs suspend the schedule (`repeated_failures`).
5. **Two budget levels.** The run cap is held against the schedule's trailing window (the longest `period_s` ever set on it, so an update to `period_s` or `start_at` cannot reset spend) before the run (`budget_exhausted` with an `agent.budget_exceeded` record when spent plus the hold would cross the cap; equal is allowed). The cap is the `run` layer of the PLT-026 port, which must also carry a `tenant` layer (`tenant_budget_missing`, ALP-031). After the run the hold settles to the cost of `meter.ai_usage` events of this tenant and run (`correlation_id`), new since each call began, each an int from 0 to the cap; an invalid value, an unreadable feed, or a charged call with no attributable event settles at the full hold (Q-599). A settle never lowers the total.
6. **Platform defaults** (placeholders per Q-156; UNVERIFIED against real pricing): cap per run and per window at most USD 50 (50,000,000 micro-USD); at most 10 active schedules per owner; cadence at least 300 s; window at most 366 days; 600 s wall clock per run; a forward clock step above 31 days, or a reading after 2100-01-01, is a clock fault.
7. **Fail closed.** Any error, including a `BaseException`, discards the run's drafts and still settles spend; a hard stop is re-raised after settling. A port bound to another tenant is `tenant_mismatch`. A backwards, too-far-forward, non-finite or non-numeric clock runs nothing and is not stored (`clock_fault`). The clock check, the re-read of the schedule, the active check and the slot claim happen atomically under one lock, so two concurrent ticks run a slot once and a disable takes effect for the next claim. Missed slots collapse into one run; a slot that comes due while a run is open is refused (`overlap`) and runs on the next tick. One schedule's failure never ends the tick for others.
8. **Audit.** Every schedule change (`schedule.created`, `.updated` with changed fields, `.disabled`, `.suspended`), every refused change (`schedule.change_refused`), every run (`agent.run_started`, `.tool_proposed`, `.run_completed`, `.run_failed`, `.run_refused`, `.budget_exceeded`) and every clock fault (`scheduler.clock_fault`) is recorded with owner, on-behalf-of user, time and slot, without args or model text. If the audit write fails, the change or run does not happen (`audit_unavailable`); a suspension still takes effect, and a run whose failure cannot be audited is reported as `audit_unavailable`.

## Alternatives rejected
- A service identity or agent role for scheduled runs: it could outrank its owner (ADR-0043, ADR-0048 item 2).
- Let scheduled runs propose R2 actions: unattended R2 proposals multiply review load; start narrow, widen by ADR.
- Rely only on per-call gateway budgets: a schedule could spend its whole tenant budget one run at a time.
- Fixed period windows keyed by `start_at`: an update re-keys the window and gives a fresh cap.

## Consequences
- Must be done: host wiring (durable store, real scheduler, gateway port) in a later slice; state is in memory, so a restart forgets spend and slots. A host watchdog must end a hung agent (the deadline is checked only at calls and drafts). `schedule.*` audit types are not in the event contract yet (Q-597); pausing on exhaustion (ALP-033, Q-598), owner and tenant-admin notification on suspension (ALP-026), and dropping queued triggers of a killed agent (ALP-025) are not built. A contract way to read committed cost per run (Q-599).
- The `authority.py` name tokens (inherited) miss some tax and payroll words; this ADR adds its own rigid-zone token list for scheduled tools only.

## Supersedes
None. Refines ADR-0048 for scheduled runs; does not edit it.
