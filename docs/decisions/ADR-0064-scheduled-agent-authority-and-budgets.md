# ADR-0064: Scheduled agents: owner authority, draft-only runs and two-level budgets

Status: Proposed
Owner: eldon
Approved by: pending (Tier 3: agent authority and budgets; needs the other founder's line-by-line review and a different-model security review)

## Context
OPR-013 adds agents that run on a cadence with no human in the turn. [ADR-0048](ADR-0048-agent-authority-propose-not-act.md) (Proposed) says OPR-013 must conform to it but does not say whose authority a scheduled run carries, how its budget is held across runs, or what happens when the owner loses access. [agent-least-privilege](../security/agent-least-privilege.md) sets the on-behalf-of user to the owner (OQ-1 open) and ALP-019, ALP-025, ALP-026, ALP-031 and ALP-033. The model-call contract ([model-call.md](../../contracts/model-call.md), [ADR-0054](ADR-0054-model-call-contract.md), Proposed) reserves and meters per call but has no standalone period reservation. First slice: `services/operate/runtime/schedule.py`.

## Decision
1. **Owner authority, never more.** A schedule's tenant and owner come from the verified principal (role ids must be a tuple of strings); a body tenant or owner that differs is refused (`tenant_mismatch`, `owner_mismatch`). Its agent role must be one of the owner's own roles (`role_escalation`); no caller-supplied role field exists. Its tools must be on that one role's agent menu (`resolve_allowlist`, `tool_not_allowed`). Reading spend or holds needs the owner's principal.
2. **Draft-only.** A scheduled tool is refused (`draft_only`) when it is R2, refused by `authority.tool_refusal`, an `export` (egress, Tool API section 11), a transition tool or a tool with `transitions[]`, or a non-read tool that is not declared `kind: write` and `entity_class: plain` (a missing kind or class is never plain), is a posting entity, or has a rigid-zone word in its entity name: matched as a substring of the lowercased name with separators removed (invoice, zatca, fatoora, wps, posting, tax, payroll, salary, payslip, ledger, journal, zakat, gosi, withholding, bank, iban; so `GLPosting`, `salesinvoice` and `journalentry` are caught), or the short words `gl` and `vat` as whole tokens after splitting on separators and camelCase (too short for substrings: global, private). False positives fail closed. Reads are `get` and `list` with `kind: read`. A run only records proposals for the human review queue; nothing executes. When the run record is made, each draft is re-checked against the schedule's tools and rebuilt as `{tool, args (copied), tainted: true}`; the run record is marked tainted.
3. **The run sees a narrow context.** The agent gets only `caller`, `complete` and `draft`: plain functions whose only captured value is an opaque run token, never a bound method, the meter or the drafts list. The port sits behind a private wrapper that forces `thread_tainted` (ALP-019), meters the run itself and enforces a wall-clock limit (`run_timeout`) counted from the moment the run is claimed, so one tenant's slow runs never shorten another's. This is defence in depth inside one process, not a sandbox: agent code is platform code, never model output, and module state stays reachable by introspection (from `ctx.complete.__globals__` code can reach the raw port and make an unmetered call; the end-of-run tool check still catches injected drafts). Moving the registry into a closure would not change this, so it stays documented, not engineered around.
4. **Re-checked at run time.** The owner's current roles are read before each run; losing the agent role suspends the schedule (`owner_permission_lost`, ALP-026), a failing role store or one that does not return a tuple is `roles_unavailable`. Tools are re-resolved before the first model call and again at the end. Only failures the schedule itself causes (`run_failed`, `tool_not_allowed`, `draft_only`) count toward suspension: three in a row suspend it (`repeated_failures`). Port refusals (meter outage, kill switch, budget), raw errors from the tool-definition store, the port factory or the port (`platform_unavailable`), `run_timeout`, `audit_unavailable` and clock faults never count. A completed run resets the count, so a schedule that fails, fails, then passes is intentionally never suspended; it keeps spending only within its budget. The owner may `resume` a suspended or disabled schedule; resuming an active one is refused (`already_active`), so it cannot reset the count (role and tools re-checked, per-owner limit applied, `schedule.resumed` audited); the spend ledger is kept and the failure count reset.
5. **Two budget levels.** Spend is kept in one ledger per tenant and owner, across all of the owner's schedules, over a trailing window equal to the longest `period_s` that owner ever set (at least one day), so disabling, recreating or updating schedules cannot reset it. Before a run, the owner's spend in the window plus the owner's open holds plus this run's cap must not exceed this schedule's `period_cap` (`budget_exhausted` with an `agent.budget_exceeded` record; equal is allowed). The run cap is the `run` layer of the PLT-026 port, which must also carry a `tenant` layer (`tenant_budget_missing`, ALP-031). After the run the hold settles to the cost of `meter.ai_usage` events of this tenant and run (`correlation_id`), new since each call began, each an int from 0 to the cap; an invalid value, an unreadable feed, or a charged call with no attributable event settles at the full hold (Q-599). A settle never lowers the total.
6. **Platform defaults** (placeholders per Q-156; UNVERIFIED against real pricing): cap per run and per schedule window at most USD 50 (50,000,000 micro-USD); because the ledger is per owner and the window is at least a day, the maximum rate per owner is USD 50 per day (the tenant layer may be lower); at most 10 active schedules per owner per tenant; cadence at least 300 s; window from one day to 366 days; 600 s wall clock per run; a reading after 2100-01-01 is a clock fault.
7. **Fail closed, recover without a restart.** Any error, including a `BaseException`, discards the run's drafts and still settles spend; a hard stop is re-raised after settling. A port bound to another tenant is `tenant_mismatch`. A non-finite, non-numeric or out-of-range reading runs nothing and is not stored (`clock_fault`). A backwards reading is a `clock_fault` until three consecutive, mutually non-decreasing backward readings arrive; then the scheduler follows the earlier clock (`scheduler.clock_rebase`) and ticks again. Spend rows are kept unchanged (a row ahead of the new time keeps counting, so the cap still binds) and slot marks only rise, so no slot id runs twice. After a far-future reading, schedules wait until the clock passes their slot mark and the owner's budget stays used until the clock passes those rows: this fails closed, and freeing it early needs an operator action (a later slice, with the durable store). A forward gap over 31 days is a fresh start (`scheduler.clock_gap`): missed slots are not caught up and spend rows are shifted by the gap, so they still count. The clock check, the re-read of the schedule, the active check and the slot claim happen atomically under one lock. Missed slots collapse into one run; a slot that comes due while a run is open is refused (`overlap`) and runs on the next tick. One schedule's failure never ends the tick for others.
8. **Audit.** Every schedule change (`schedule.created`, `.updated` with changed fields, `.disabled`, `.suspended`, `.resumed`), every refused change (`schedule.change_refused`), every run (`agent.run_started`, `.tool_proposed`, `.run_completed`, `.run_failed`, `.run_refused`, `.budget_exceeded`) and every clock event (`scheduler.clock_fault`, `.clock_gap`, `.clock_rebase`) is recorded with owner, on-behalf-of user, time and slot, without args or model text. If the audit write fails, the change or run does not happen (`audit_unavailable`); a suspension still takes effect, and a run whose failure cannot be audited is reported as `audit_unavailable`.

## Alternatives rejected
- A service identity or agent role for scheduled runs: it could outrank its owner (ADR-0043, ADR-0048 item 2).
- Let scheduled runs propose R2 actions: unattended R2 proposals multiply review load; start narrow, widen by ADR.
- Rely only on per-call gateway budgets: a schedule could spend its whole tenant budget one run at a time.
- Fixed period windows keyed by `start_at`: an update re-keys the window and gives a fresh cap.
- A ledger per schedule id: disabling and recreating a schedule gives a fresh budget.
- Counting every failure toward suspension: a platform outage of three slots would suspend every schedule.

## Consequences
- Must be done: host wiring (durable store, real scheduler, gateway port) in a later slice; state is in memory, so a restart forgets spend and slots. A host watchdog must end a hung agent (the deadline is checked only at calls and drafts). `schedule.*` audit types are not in the event contract yet (Q-597); pausing on exhaustion (ALP-033, Q-598), owner and tenant-admin notification on suspension (ALP-026), and dropping queued triggers of a killed agent (ALP-025) are not built. A contract way to read committed cost per run (Q-599).
- The `authority.py` name tokens (inherited) miss some tax and payroll words; this ADR adds its own rigid-zone token list for scheduled tools only.

## Supersedes
None. Refines ADR-0048 for scheduled runs; does not edit it.
